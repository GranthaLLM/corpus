# Grantha corpus

Benchmark corpus for the Sarvamoola/Grantha LLM project (advised by Dr. Prathosh, IISc). Companion to the "Grantha LLM: Internal Benchmarking Corpus" doc, which lists the works and the source chosen for each.

Private repo. Internal benchmark, not training data, not for release (several English sources are in copyright).

## What this is for

A model is given the `sanskrit` of a unit and asked to translate it. The output is scored against the `english` of the same unit. `tools/validate.py` checks every file against the format below.

The English is a **reference to score against**, not something the project needs to read. So any reasonable published translation is acceptable, as long as it translates exactly the passage the Sanskrit holds. That one rule drives most of the format:

- `sanskrit` and `english` of a unit must cover the same passage, nothing more, nothing less.
- If a side is missing, the unit is skipped rather than filled with a guess.
- Dialogue and narrative sections were chosen on purpose (Uddhava Gita, Kapila to Devahuti, Yaksha Prashna, Vidura Niti, Sanatsujatiya, Harivamsha) because their translations vary less between translators than doctrinal prose does.

## At a glance

- 41 files, 16,762 units. Units without English are skipped when scoring: Bhattasangraha (62) and the Sanskrit-only Madhva bhashya units of Aitareya (27).
- Three folders: `philosophical/` (Gita, Brahmasutra and other shastra works), `upanishads/` (ten Upanishads, Shankara and Madhva tracks each), `sahitya/` (Mahabharata excerpts, Bhagavata excerpts, Harivamsha, Kumarasambhava, Shatakatraya).
- All Sanskrit is Devanagari. English is English.
- `schema.json` is the JSON Schema for a work file. `tools/` holds the scripts that built the files.

Where each source comes from is in `source_sanskrit` / `source_english` inside each file.

Two things to know when reading the list:

- **Two tracks per Upanishad.** Every Upanishad appears twice, once with Śaṃkara's commentary (Advaita) and once with Madhva's (Dvaita). The mula is the same text, the commentary and its English differ. The same holds for the Gita (three tracks: Shankara, Ramanuja, Madhva) and the Brahmasutras (Shankara, Ramanuja via Sri Bhashya, Madhva). This allows the same verse to be compared across traditions.
- **Not every file has commentary.** Harivamsha, Kumarasambhava, Shatakatraya, the Mahabharata excerpts and the Mitrasamgraha philosophical texts are independent works with no commentary layer.

## Data format

### File

Every file is one JSON object. Fields:

| Field | Meaning |
|---|---|
| `id`, `text`, `tradition`, `commentator` | Which work this is |
| `script` | Always `Devanagari` (script of every `sanskrit` string) |
| `units` | The list of units, in text order |
| `source_sanskrit`, `source_english` | Where each side came from: citation, URL, licence. A list when two sources were used |
| `alignment` | `row_aligned` (the source pairs them), `by_ref` (two sources joined on ref), `unaligned` |
| `reference_type` | `translation` (english translates the sanskrit), `interpretive` (the translator's reading, e.g. Pandurangi's Aitareya), `summary` (Bhattasangraha). Filter on it when scoring |
| `english_rights` | Best-effort rights status: `public_domain`, `free_to_copy_per_author`, `cc_by_sa`, `in_copyright_or_unclear` |
| `bundled`, `needs_ocr`, `slice_of` | Source flags |
| `notes` | Anything a user must know: source quirks, gaps, edits made |

### Unit

```json
{ "ref": "...", "kind": "verse|sutra|prose|group", "scope": "...", "sanskrit": "...", "english": "...", "parts": [...], "meta": {...} }
```

- `ref`: the numbering the source uses, unique inside the file. Examples: `1.1.1` (Brahmasutra), `3/4` (Gita chapter/verse, Madhva files), `3.25.13` (Bhagavata), `1.4.4-1.5.1` (a range), plus named units such as `intro`, `mangalacharana`, `colophon209`, `bhashya`.
- `kind`: the form of the text. `verse`, `sutra`, `prose`, or `group` (several verses the source joins into one unit).
- `scope`: what the pair `sanskrit` / `english` covers. This is the key field.
- `sanskrit` / `english`: the scored pair. `english` translates exactly what `sanskrit` holds. Null on either side means the unit is skipped.
- `parts` (optional, never scored): the pieces of a commentary unit, each `{"role": "mula|bhashya|tatparya", "sanskrit": ..., "english": ...}`.
- `meta` (optional): source-specific extras, such as the Bhagavata edit log.

### Scope

| `scope` | The pair holds | Used for |
|---|---|---|
| `text` | An independent work, no mula/commentary split | Harivamsha, Kumarasambhava, Shatakatraya, Mahabharata excerpts, Sarvadarshanasamgraha, Samkhyakarika, MBTN, ... |
| `mula` | The verse or sutra only | Bhagavata excerpts, Aitareya Madhva, and verses whose commentary has no English |
| `commentary` | The commentary or intro prose only | Brihadaranyaka Madhva, Chandogya Madhva, intros, colophons |
| `mula+commentary` | The verse or sutra first, then its commentary, joined with a newline | Gita, Brahmasutra, most Upanishad verses |

## Structure types, with examples

Long strings are cut with `...` here. Every example is a real unit.

### 1. Independent work (`scope: text`)

One passage, one translation. No parts. Harivamsha, `ref` `2363`:

```json
{
  "ref": "2363",
  "kind": "verse",
  "scope": "text",
  "sanskrit": "प्रीयन्ते पितरस् तस्य प्रादुर्भावानुकीर्तनात् । विष्णोर् अमितवीर्यस्य यः शृणोति कृताञ्जलिः ॥",
  "english": "The ancestral manes of the person are delighted who, with folded palms, listens to or recites the incarnations of Vishnu of unlimited power."
}
```

### 2. Mula plus commentary, fully paired (`scope: mula+commentary`)

The pair is the sutra followed by its bhashya. `parts` holds the same text split by role, so you can score the sutra alone or the bhashya alone. `bsb_madhva`, `1.1.2`:

```json
{
  "ref": "1.1.2",
  "kind": "sutra",
  "scope": "mula+commentary",
  "sanskrit": "॥ ॐ जन्माद्यस्य यतः ॐ॥ १/१/२॥\nब्रह्मणो लक्षणमाह-  जन्माद्यस्य यतः। ...",
  "english": "That is Brahman) from which the origin, etc., of this (universe proceed).\n(Brahman is that) from whom the origin, ...",
  "parts": [
    { "role": "mula",
      "sanskrit": "॥ ॐ जन्माद्यस्य यतः ॐ॥ १/१/२॥",
      "english": "That is Brahman) from which the origin, etc., of this (universe proceed)." },
    { "role": "bhashya",
      "sanskrit": "ब्रह्मणो लक्षणमाह-  जन्माद्यस्य यतः। ...",
      "english": "(Brahman is that) from whom the origin, subsistence, dissolution, ..." }
  ]
}
```

The text is stored three times (the combined pair, the mula part, the bhashya part). That is deliberate: the combined pair is what a single-field eval reads; the parts give separate mula and commentary scores.

### 3. Commentary part with no English (part outside the pair)

Sources do not always translate every piece. When a part has Sanskrit but no English, it stays in `parts` and is left out of the pair, so the pair never mixes in text with no counterpart. `bg_madhva`, `3/4`: the Tatparya Nirnaya has Sanskrit but no English in the source, so the pair holds mula and bhashya only:

```json
{
  "ref": "3/4",
  "kind": "verse",
  "scope": "mula+commentary",
  "sanskrit": "न कर्मणामनारम्भान्नैष्कर्म्यं पुरुषोऽश्नुते। ...॥ ३/४॥\nइतश्च नियोक्ष्यामीत्याह- ...",
  "english": "Not by abstention of Action does a man attain freedom from Action; ...",
  "parts": [
    { "role": "mula",     "sanskrit": "न कर्मणामनारम्भा...", "english": "Not by abstention of Action ..." },
    { "role": "bhashya",  "sanskrit": "इतश्च नियोक्ष्यामीत्याह- ...", "english": "In this verse Sri Krishna refers to ..." },
    { "role": "tatparya", "sanskrit": "ज्ञानप्रचुरो योगो ज्ञानयोगः। ..." }
  ]
}
```

### 4. Mula only, commentary kept aside (`scope: mula`)

Bhagavata verses are scored on the verse alone. Madhva's commentary sits in `parts` as Sanskrit only. This unit also shows `meta` (see Bhagavata note below). `bhagavata_kapila`, `3.25.13`:

```json
{
  "ref": "3.25.13",
  "kind": "verse",
  "scope": "mula",
  "sanskrit": "श्रीभगवानुवाच-\nयोग आध्यात्मिकः पुंसां मतो निःश्रेयसाय मे। ...",
  "english": "The Lord answered: The yoga system which relates to the Lord and the individual ...",
  "parts": [
    { "role": "mula",    "sanskrit": "श्रीभगवानुवाच-\nयोग आध्यात्मिकः पुंसां ..." },
    { "role": "bhashya", "sanskrit": "“परमात्मादिकं देहे यदध्यात्मं तदीरितम्” इति च। ..." }
  ],
  "meta": {
    "align": "content",
    "english_edits": [ { "rule": "(the) Supreme Personality of Godhead -> the Lord", "count": 1 } ],
    "vedabase_texts": [ "13-13" ],
    "english_verbatim": "The Personality of Godhead answered: ..."
  }
}
```

The Bhagavata `english` is Prabhupada's translation with terms neutralised for this benchmark (so a model is not scored on sectarian vocabulary). The text as published is kept in `meta.english_verbatim`, so cite that.

### 5. Group (`kind: group`)

Sources split verses differently. Where the Sanskrit and the English cover different verse boundaries, the verses are merged into one unit so both sides hold the identical passage. `bhagavata_kapila`, `3.25.39-40`:

```json
{
  "ref": "3.25.39-40",
  "kind": "group",
  "scope": "mula",
  "sanskrit": "इमं लोकं तथैवामुमात्मानमुभयायिनम्। आत्मानमनु ये चेमे ...",
  "english": "Thus the devotee who worships Me, the all-pervading Lord of the universe ...",
  "meta": { "align": "content", "vedabase_texts": [ "39-40" ], "english_verbatim": "..." }
}
```

Gita Madhva uses refs like `3/20-26` for the same reason: Sonde translates those verses together.

### 6. Commentary only (`scope: commentary`)

Used where the source gives the commentary as one continuous block, not tied to individual verses, and for intros and closing lines. `kena_madhva`, `bhashya`:

```json
{
  "ref": "bhashya",
  "kind": "prose",
  "scope": "commentary",
  "sanskrit": "वैजयन्ते समासीनमेकान्ते चतुराननम्।\nविष्णोर्विविदिषुस्तत्त्वं पर्यपृच्छ...",
  "english": "Thus, sitting in his abode, Vaijayanti, the four-faced Brahma extolled..."
}
```

### 7. Opening and closing units

The start of a work is its own units, so an invocation is not glued to the first verse. Typical refs: `intro` (shanti invocation and the commentator's mangalacharana), `intro-2` (a repeated closing shanti), `colophon*` (closing lines). `bsb_madhva`, `mangalacharana`:

```json
{
  "ref": "mangalacharana",
  "kind": "verse",
  "scope": "commentary",
  "sanskrit": "ॐ॥ नारायणं गुणैः सर्वैरुदीर्णं दोषवर्जितम्।  ज्ञेयं गम्यं गुरूंश्चापि नत्वा सूत्रार्थ उच्यते॥",
  "english": "Having bowed to Narayana, who is full of excellence in all qualities and free from defects, ..."
}
```

Colophon English was written for this corpus when the source had none (`meta.english_source` says so).

### 8. Interpretive translation (`reference_type: interpretive`)

Where the only English is a translator's reading of the passage, not a close rendering, the file is marked `interpretive` at file level. `aitareya_madhva` (Pandurangi's translation, as Madhva reads it), `2.1.2.3`:

```json
{
  "ref": "2.1.2.3",
  "kind": "prose",
  "scope": "mula",
  "sanskrit": "अथाध्यात्मम्॥ पुरुष एवोक्थमयमेव महान् प्रजापतिरहमुक्थमस्मीति विद्यात्। ...",
  "english": "Now Adhyātma forms of the Supreme God. The form of the Supreme God present in th..."
}
```

Filter on `reference_type` when scoring, so literal translations and interpretive ones are not averaged together.

### Units without `parts`

Some `mula+commentary` units hold the pair without `parts` because the source gives mula and commentary as one block (all of `sribhashya_ramanuja`, 539 units). For those the pair is the only copy and there is no separate mula or commentary score.

## Addressing a unit

A unit or one of its parts is addressed as `file:ref` or `file:ref.role`, where `file` is the file name without `.json` and `role` is `mula`, `bhashya` or `tatparya`:

- `bsb_madhva:1.1.1` is the sutra and its bhashya together, with the split parts.
- `bsb_madhva:1.1.1.mula` is the sutra alone, `bsb_madhva:1.1.1.bhashya` the commentary alone.
- `bg_madhva:3/4.tatparya` and `aitareya_madhva:mangalacharana` work the same way.

`python3 tools/lookup.py bsb_madhva:1.1.1.bhashya` prints the text, `--json` returns it as JSON. A unit that holds its pair without parts (all of `sribhashya_ramanuja`) answers only to the whole address. Run `python3 tools/test_lookup.py` to test it.

## Known issues

- **Units without English** (skipped when scoring): Bhattasangraha 62 units (its English is Pandurangi's summary, `reference_type: summary`, and exists for only part of the work), Aitareya Madhva bhashya 27 units (Pandurangi only summarises it; `reference_type: interpretive` for the rest of that file).
- **English written for this corpus** (no source translates it; named in each file's notes): Isa Madhva 16, 17, 18; Katha Shankara 1.3.10-12 and nine commentary passages Sastri skips; bsb_madhva 1.1.24, 1.3.1, 1.3.43, 1.4.29, 2.1.8, 2.4.1 and the closing line of 3.3.68, 2.3.39, 3.1.22; bg_shankara 5.27, 7.30, 18.25; brihadaranyaka_shankara 6.4.2; brihadaranyaka_madhva last unit (Panchagni verses and closing salutations; some verses there are corrupt in Setutila, so those lines are tentative); bg_ramanuja 1.1; the colophon units.
- **Harivamsha** is now 3,561 verse units (it was 7,206 half-verse rows, where Dutt's English often ran into the neighbouring row). 72 units were dropped because their English belongs to other passages (source rows 4962-4995, 5046-5115, 5619-5686, 6881-6927 in part, 7379-7468), and three stretches (rows 2953-2954, 3700-3708, 5954-5970) were merged where the English ran behind the Sanskrit. A hand audit of 60 random units after that found 6 still misaligned (about 10%): English that carries the neighbouring half, or an odd single unit whose English is of another passage.
- **Known mismatches:** sanatsujatiya row 28124 (Sanskrit row is a fragment, English covers several rows); three validator warnings remain on purpose, all terse translations of longer Sanskrit (sribhashya_ramanuja 4.3.3, brihadaranyaka_shankara 3.2.9) or the fragment above; Mitrasamgraha rows in the Mahabharata files whose prose has no Sanskrit row.
- **Shankara Upanishad and Brahma Sutra files** still have open items listed in `spotcheck/shankara_upanishad_bhashya_flaws.md` and `spotcheck/bsb_shankara_mismatches.md` (for example sutra-translation heads missing in bsb_shankara 3.1.1, 4.1.1, 4.3.1, 4.4.1, mid-unit spills in several bsb_shankara units, 16 avatarika spills in Brihadaranyaka Shankara). Treat those files as less reliable than the Madhva Upanishad files.
- **Not hand-verified:** all checks so far are scripted (alignment audits, length ratios, duplicate detection) plus reading of flagged units. No random sample has been checked by hand yet.
