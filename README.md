# Grantha corpus

Benchmark corpus for the Sarvamoola/Grantha LLM project (advised by Dr. Prathosh, IISc). Companion to the "Grantha LLM: Internal Benchmarking Corpus" doc, which lists the 27 works and the source chosen for each.

Eval use: the model is given the `sanskrit` field, produces a translation, and that is scored against the `english` field of the same unit.

## Layout

```
philosophical/   Philosophical works (Gita bhashyas, Brahmasutra bhashyas, Nyaya, Samkhya, ...)
upanishads/      One file per Upanishad per commentator track, e.g. isa_shankara.json, isa_madhva.json
sahitya/         Sahitya Sanskrit (Mahabharata excerpts, Harivamsha, Kumarasambhava, Shatakatraya, ...)
schema.json      JSON Schema for a work file
tools/           Scripts that built the files from the cached sources (need a local source cache, see below)
```

## Schema

See `schema.json`. Every file has `id`, `text`, `tradition`, `units[]`, `source_sanskrit`, `source_english`, `bundled`, `needs_ocr`, `notes`, plus:

- `units[].ref`: numbering as the source uses it (verse, sutra, TSV row, section heading)
- `units[].sanskrit` / `units[].english`: always paired, verbatim from the cited source. `english` is the translation of exactly what `sanskrit` holds.
- `units[].sanskrit_mula` / `sanskrit_bhashya`: split when `sanskrit` is mula + commentary
- `units[].english_mula` / `english_bhashya`: same split on the English side (Madhva tracks); in wisdomlib Shankara tracks `english_bhashya` is the English of Shankara's commentary, which has no Sanskrit counterpart on that source
- `alignment`: `row_aligned` (source pairs them), `by_ref` (two sources joined on ref, not verified), `unaligned` (one side missing or not split per unit)
- `slice_of`: row range when a file is a slice of a larger source file
- `script`: script of `sanskrit` (IAST, Devanagari, padaccheda-split IAST)
- `notes`: anything a user must know (source quirks, gaps, deviations from the corpus doc)

Nothing is invented: a string is either verbatim from the cited source or `null`. A `null` `english` with `needs_ocr` or a note means the source is a scan that pass 2 will fill.

## Two-pass approach

1. **Pass 1, clean sources.** Advaita Sharada (Sringeri, Vani Vilas edition) for every Shankara Sanskrit text (Gita, Brahmasutra, all Upanishads), Setutila JSON (CC0) for Madhva Sanskrit, wisdomlib for English of the Upanishads, Mitrasamgraha TSVs, GRETIL plaintext. No OCR. Where the paired side is a scan, that side is `null` until pass 2.
2. **Pass 2, OCR backfill.** The archive.org scans marked `needs_ocr` in the corpus doc. `_djvu.txt` as a stopgap, Sarvam Vision or Tesseract where quality is too poor. Each refined file records the OCR method in `notes`.

## Rebuilding

`tools/` expects a cache of the raw sources in the directory named by `GRANTHA_RAW` (GRETIL txt, Mitrasamgraha TSV, Setutila `set_*.json`, `wl_cache/` of wisdomlib page text). The cache is not committed.
