# Grantha corpus

Benchmark corpus for the Sarvamoola/Grantha LLM project (advised by Dr. Prathosh, IISc). Companion to the "Grantha LLM: Internal Benchmarking Corpus" doc, which lists the works and the source chosen for each.

Private repo. Internal benchmark, not training data, not for release (several English sources are in copyright, see Licences).

## What this is for

A model is given the `sanskrit` of a unit and asked to translate it. The output is scored against the `english` of the same unit. `tools/validate.py` checks every file against the format below.

The English is a **reference to score against**, not something the project needs to read. So any reasonable published translation is acceptable, as long as it translates exactly the passage the Sanskrit holds. That one rule drives most of the format:

- `sanskrit` and `english` of a unit must cover the same passage, nothing more, nothing less.
- If a side is missing, the unit is skipped rather than filled with a guess.
- Dialogue and narrative sections were chosen on purpose (Uddhava Gita, Kapila to Devahuti, Yaksha Prashna, Vidura Niti, Sanatsujatiya, Harivamsha) because their translations vary less between translators than doctrinal prose does.

## At a glance

- 40 files, 20,213 units. Only Bhattasangraha has units without English (62), and those are skipped when scoring.
- Three folders: `philosophical/` (Gita, Brahmasutra and other shastra works), `upanishads/` (ten Upanishads, Shankara and Madhva tracks each), `sahitya/` (Mahabharata excerpts, Bhagavata excerpts, Harivamsha, Kumarasambhava, Shatakatraya).
- All Sanskrit is Devanagari. English is English.
- `schema.json` is the JSON Schema for a work file. `tools/` holds the scripts that built the files.

Where each source comes from is in the Status table further down, and in `source_sanskrit` / `source_english` inside each file.

Two things to know when reading the list:

- **Two tracks per Upanishad.** Every Upanishad appears twice, once with Śaṃkara's commentary (Advaita) and once with Madhva's (Dvaita). The mula is the same text, the commentary and its English differ. The same holds for the Gita (three tracks: Shankara, Ramanuja, Madhva) and the Brahmasutras (Shankara, Ramanuja via Sri Bhashya, Madhva). This allows the same verse to be compared across traditions.
- **Not every file has commentary.** Harivamsha, Kumarasambhava, Shatakatraya, the Mahabharata excerpts and the Mitrasamgraha philosophical texts are independent works with no commentary layer.

## Data format

### File

Every file is one JSON object. Fields:

| Field | Meaning |
|---|---|
| `id`, `text`, `tradition`, `commentator` | Which work this is |
| `script` | Always `Devanagari` (script of every `sanskrit` string) |
| `units` | The list of units, in text order |
| `source_sanskrit`, `source_english` | Where each side came from: citation, URL, licence. A list when two sources were used |
| `alignment` | `row_aligned` (the source pairs them), `by_ref` (two sources joined on ref), `unaligned` |
| `reference_type` | `translation` (english translates the sanskrit), `interpretive` (the translator's reading, e.g. Pandurangi's Aitareya), `summary` (Bhattasangraha). Filter on it when scoring |
| `english_rights` | Best-effort rights status: `public_domain`, `free_to_copy_per_author`, `cc_by_sa`, `in_copyright_or_unclear` |
| `bundled`, `needs_ocr`, `slice_of` | Source flags |
| `notes` | Anything a user must know: source quirks, gaps, edits made |

### Unit

```json
{ "ref": "...", "kind": "verse|sutra|prose|group", "scope": "...", "sanskrit": "...", "english": "...", "parts": [...], "meta": {...} }
```

- `ref`: the numbering the source uses, unique inside the file. Examples: `1.1.1` (Brahmasutra), `3/4` (Gita chapter/verse, Madhva files), `3.25.13` (Bhagavata), `1.4.4-1.5.1` (a range), plus named units such as `intro`, `mangalacharana`, `colophon209`, `bhashya`.
- `kind`: the form of the text. `verse`, `sutra`, `prose`, or `group` (several verses the source joins into one unit).
- `scope`: what the pair `sanskrit` / `english` covers. This is the key field.
- `sanskrit` / `english`: the scored pair. `english` translates exactly what `sanskrit` holds. Null on either side means the unit is skipped.
- `parts` (optional, never scored): the pieces of a commentary unit, each `{"role": "mula|bhashya|tatparya", "sanskrit": ..., "english": ...}`.
- `meta` (optional): source-specific extras, such as the Bhagavata edit log.

### Scope

| `scope` | The pair holds | Used for |
|---|---|---|
| `text` | An independent work, no mula/commentary split | Harivamsha, Kumarasambhava, Shatakatraya, Mahabharata excerpts, Sarvadarshanasamgraha, Samkhyakarika, MBTN, ... |
| `mula` | The verse or sutra only | Bhagavata excerpts, Aitareya Madhva, and verses whose commentary has no English |
| `commentary` | The commentary or intro prose only | Brihadaranyaka Madhva, Chandogya Madhva, intros, colophons |
| `mula+commentary` | The verse or sutra first, then its commentary, joined with a newline | Gita, Brahmasutra, most Upanishad verses |

## Structure types, with examples

Long strings are cut with `...` here. Every example is a real unit.

### 1. Independent work (`scope: text`)

One passage, one translation. No parts. Harivamsha, `ref` `6`:

```json
{
  "ref": "6",
  "kind": "prose",
  "scope": "text",
  "sanskrit": "तल् लभ्यते व्यासवचः प्रमाणं गीतं च वाल्मीकिमहर्षिणा च ।",
  "english": "Vyasa's word is the proof hereof and this has also been said by the great Rishi Vālmiki."
}
```

### 2. Mula plus commentary, fully paired (`scope: mula+commentary`)

The pair is the sutra followed by its bhashya. `parts` holds the same text split by role, so you can score the sutra alone or the bhashya alone. `bsb_madhva`, `1.1.2`:

```json
{
  "ref": "1.1.2",
  "kind": "sutra",
  "scope": "mula+commentary",
  "sanskrit": "॥ ॐ जन्माद्यस्य यतः ॐ॥ १/१/२॥\nब्रह्मणो लक्षणमाह-  जन्माद्यस्य यतः। ...",
  "english": "That is Brahman) from which the origin, etc., of this (universe proceed).\n(Brahman is that) from whom the origin, ...",
  "parts": [
    { "role": "mula",
      "sanskrit": "॥ ॐ जन्माद्यस्य यतः ॐ॥ १/१/२॥",
      "english": "That is Brahman) from which the origin, etc., of this (universe proceed)." },
    { "role": "bhashya",
      "sanskrit": "ब्रह्मणो लक्षणमाह-  जन्माद्यस्य यतः। ...",
      "english": "(Brahman is that) from whom the origin, subsistence, dissolution, ..." }
  ]
}
```

The text is stored three times (the combined pair, the mula part, the bhashya part). That is deliberate: the combined pair is what a single-field eval reads; the parts give separate mula and commentary scores.

### 3. Commentary part with no English (part outside the pair)

Sources do not always translate every piece. When a part has Sanskrit but no English, it stays in `parts` and is left out of the pair, so the pair never mixes in text with no counterpart. `bg_madhva`, `3/4`: the Tatparya Nirnaya has Sanskrit but no English in the source, so the pair holds mula and bhashya only:

```json
{
  "ref": "3/4",
  "kind": "verse",
  "scope": "mula+commentary",
  "sanskrit": "न कर्मणामनारम्भान्नैष्कर्म्यं पुरुषोऽश्नुते। ...॥ ३/४॥\nइतश्च नियोक्ष्यामीत्याह- ...",
  "english": "Not by abstention of Action does a man attain freedom from Action; ...",
  "parts": [
    { "role": "mula",     "sanskrit": "न कर्मणामनारम्भा...", "english": "Not by abstention of Action ..." },
    { "role": "bhashya",  "sanskrit": "इतश्च नियोक्ष्यामीत्याह- ...", "english": "In this verse Sri Krishna refers to ..." },
    { "role": "tatparya", "sanskrit": "ज्ञानप्रचुरो योगो ज्ञानयोगः। ..." }
  ]
}
```

### 4. Mula only, commentary kept aside (`scope: mula`)

Bhagavata verses are scored on the verse alone. Madhva's commentary sits in `parts` as Sanskrit only. This unit also shows `meta` (see Bhagavata note below). `bhagavata_kapila`, `3.25.13`:

```json
{
  "ref": "3.25.13",
  "kind": "verse",
  "scope": "mula",
  "sanskrit": "श्रीभगवानुवाच-\nयोग आध्यात्मिकः पुंसां मतो निःश्रेयसाय मे। ...",
  "english": "The Lord answered: The yoga system which relates to the Lord and the individual ...",
  "parts": [
    { "role": "mula",    "sanskrit": "श्रीभगवानुवाच-\nयोग आध्यात्मिकः पुंसां ..." },
    { "role": "bhashya", "sanskrit": "“परमात्मादिकं देहे यदध्यात्मं तदीरितम्” इति च। ..." }
  ],
  "meta": {
    "align": "content",
    "english_edits": [ { "rule": "(the) Supreme Personality of Godhead -> the Lord", "count": 1 } ],
    "vedabase_texts": [ "13-13" ],
    "english_verbatim": "The Personality of Godhead answered: ..."
  }
}
```

The Bhagavata `english` is Prabhupada's translation with terms neutralised for this benchmark (so a model is not scored on sectarian vocabulary). The text as published is kept in `meta.english_verbatim`, so cite that.

### 5. Group (`kind: group`)

Sources split verses differently. Where the Sanskrit and the English cover different verse boundaries, the verses are merged into one unit so both sides hold the identical passage. `bhagavata_kapila`, `3.25.39-40`:

```json
{
  "ref": "3.25.39-40",
  "kind": "group",
  "scope": "mula",
  "sanskrit": "इमं लोकं तथैवामुमात्मानमुभयायिनम्। आत्मानमनु ये चेमे ...",
  "english": "Thus the devotee who worships Me, the all-pervading Lord of the universe ...",
  "meta": { "align": "content", "vedabase_texts": [ "39-40" ], "english_verbatim": "..." }
}
```

Gita Madhva uses refs like `3/20-26` for the same reason: Sonde translates those verses together.

### 6. Commentary only (`scope: commentary`)

Used where the source gives the commentary as one continuous block, not tied to individual verses, and for intros and closing lines. `kena_madhva`, `bhashya`:

```json
{
  "ref": "bhashya",
  "kind": "prose",
  "scope": "commentary",
  "sanskrit": "वैजयन्ते समासीनमेकान्ते चतुराननम्।\nविष्णोर्विविदिषुस्तत्त्वं पर्यपृच्छ...",
  "english": "Thus, sitting in his abode, Vaijayanti, the four-faced Brahma extolled..."
}
```

### 7. Opening and closing units

The start of a work is its own units, so an invocation is not glued to the first verse. Typical refs: `intro` (shanti invocation and the commentator's mangalacharana), `intro-2` (a repeated closing shanti), `colophon*` (closing lines). `bsb_madhva`, `mangalacharana`:

```json
{
  "ref": "mangalacharana",
  "kind": "prose",
  "scope": "commentary",
  "sanskrit": "ॐ॥ नारायणं गुणैः सर्वैरुदीर्णं दोषवर्जितम्।  ज्ञेयं गम्यं गुरूंश्चापि नत्वा सूत्रार्थ उच्यते॥",
  "english": "Having bowed to Narayana, who is full of excellence in all qualities and free from defects, ..."
}
```

Colophon English was written for this corpus when the source had none (`meta.english_source` says so).

### 8. Interpretive translation (`reference_type: interpretive`)

Where the only English is a translator's reading of the passage, not a close rendering, the file is marked `interpretive` at file level. `aitareya_madhva` (Pandurangi's translation, as Madhva reads it), `2.1.2.3`:

```json
{
  "ref": "2.1.2.3",
  "kind": "prose",
  "scope": "mula",
  "sanskrit": "अथाध्यात्मम्॥ पुरुष एवोक्थमयमेव महान् प्रजापतिरहमुक्थमस्मीति विद्यात्। ...",
  "english": "Now Adhyātma forms of the Supreme God. The form of the Supreme God present in th..."
}
```

Filter on `reference_type` when scoring, so literal translations and interpretive ones are not averaged together.

### Units without `parts`

Some `mula+commentary` units hold the pair without `parts` because the source gives mula and commentary as one block (all of `sribhashya_ramanuja`, 539 units). For those the pair is the only copy and there is no separate mula or commentary score.

## Why it is built this way

- **One pair per unit, scored against a reference.** The eval reads `sanskrit` and `english`. Everything else is metadata.
- **Scope on every unit.** Works differ: some are verse only, some verse plus commentary, some commentary only. Without `scope` a scorer cannot tell whether `english` should include the commentary. It also lets scores be reported separately for mula and for commentary, which behave differently (commentary translations are more interpretive and noisier).
- **`parts` instead of more fields.** A commentary has several pieces (verse, bhashya, tatparya) and the source translates some and not others. `parts` keeps every piece, and the pair keeps only what has a counterpart on both sides, so the English never claims to translate text it does not cover.
- **Groups.** Two editions rarely split verses alike. Merging to the smallest passage both sides share keeps the pair exact.
- **Intros and colophons as units.** They are real text a model may be asked to translate, and keeping them out of the first verse keeps verse units clean.
- **Two tracks per Upanishad and per Gita/Brahmasutra.** The project concerns reading across traditions, and a commentary-grounded check needs the commentary tied to its own verse.
- **`reference_type` and `english_rights`.** The reference quality differs by source. Filtering on these keeps weak or restricted references out of a headline score.
- **Source cited, nothing invented.** A string is verbatim from the cited source or `null`. Edits (OCR cleanup, term neutralisation, trimmed overrun) are listed in `notes` or `meta`.

## Conventions

- Build order: the `build_*.py` scripts, then `normalize.py`, then `layout.py` (old per-field layout to the layout above), then `clean_english.py` (drops embedded Sanskrit verses and page headers from `english`), then `validate.py`. `status.py` regenerates the tables in this README.
- One clean `english` per unit. The source is named in `notes` and `source_english`, not on each unit.
- When the Sanskrit and English of a source split a passage differently, group the units. When a side does not exist, leave it `null` rather than guess, and record the OCR method in `notes`.
- Rewrite JSON with `indent=1` (`tools/common.write`) so diffs stay small.

## Known issues

What a user of the corpus should know before relying on a file. The unit count in the status table includes all of these.

- **Brahmasutra, Madhva track**: Subba Rau's lead-in to the next sutra ("the Sutrakara says :") was moved or cut from the end of 58 bhashya units; 7 units (2.1.16, 2.3.36, 2.4.22, 3.2.33, 3.2.36, 3.3.42, 3.3.53) end with an objection followed by such a lead-in and were left as they are.
- **`parts` and the pair**: in some files the combined `sanskrit`/`english` is not exactly the join of the `parts` that have both sides (some by design, because `scope` selects a subset; some possibly drift from later edits). A validator rule for this is not written yet.
- **Left-out units**: every file except Bhattasangraha holds only units with both Sanskrit and english. About 55 Sanskrit units with no english in any source are left out (Aitareya Madhva's 26 commentary units, 12 Brihadaranyaka verses Madhavananda omits, 6 Shatakatraya verses, a few intros); each file's notes list its refs. Colophon units were restored with a formulaic english written for this corpus (`meta.english_source`), and many intro units were recovered from the scans or wisdomlib.
- **Alignment audit**: a LaBSE sentence-embedding sequence test (`tools/labse_align_audit.py`) found no offset runs left in any file after repairs: Bhagavata Kapila/Uddhava were re-paired by content (Setutila and Vedabase verse numbers drift), 12 Harivamsha stretches and one each in Sarvadarshanasamgraha and Vidura Niti where english sat 1-3 rows off were merged into single units. The test cannot see a unit whose neighbours are all equally off, and LaBSE is weak on verse, so some Bhagavata pairs (roughly 1 in 7 in a sample) can still be wrong.
- **Bhattasangraha** (`reference_type: summary`): english is Pandurangi's summary of each adhikarana, not a translation, and 57 units have none; its Sanskrit is unproofread OCR.
- **Chandogya, Madhva track** (`translation`): english is Sonde's, matched to units by decoded Sanskrit; units are Setutila's khanda ranges (up to 5k-37k chars), and some undecoded legacy tokens remain.
- **Chandogya, Shankara track**: Jha's english is clause by clause with the sentence-final periods stripped; in the 35 merged units the Sanskrit and the english both follow the text order (mula, its commentary, the next mula, its commentary); some intro units have no english.
- **Aitareya, Madhva track** (`interpretive`): units are passages of the Upanishad with Pandurangi's translation as Madhva reads it; about 12% of the mula text is in no unit, and Madhva's commentary is Sanskrit-only (`-bhashya` units).
- **Gita, Shankara track**: about 24 units still have english somewhat shorter than the Sanskrit commentary (52 others were replaced with Warrier fuller translation); 14 units have none; OCR slips in diacritics (`^`, `~`) remain.
- **Gita, Ramanuja track**: the english of a few verses covers two verses jointly (those are merged units); translator's bracketed notes and running heads were stripped, but OCR slips can remain; intro units have no english.
- **Gita, Madhva track**: a unit pairs only the parts whose Sanskrit and english are comparable in length, so many commentary parts sit in `parts` outside the scored pair; the Sanskrit decoded from Sonde's legacy-font PDF can contain stray misspellings; 12 colophon units have none; 7/30, 8/8 and 18/33 were filled from Sonde.
- **Harivamsha**: the Mitrasamgraha rows carried critical-apparatus text in front of some verses, which was stripped; 106 units whose Sanskrit was apparatus only or whose rows were shifted against the english were dropped.
- **Shatakatraya**: 6 verses have no english (1.39, 1.109, 3.40, 3.98, 3.100 twice) plus 2.101 (no counterpart in Gopalachariar). Shringarashataka English is partly Kennedy 1913 (free paraphrase) and partly Gopalachariar 1954 (in copyright).
- **Invocations**: the opening shanti and mangalacharana of `katha_madhva`, `prashna_madhva` and `isa_madhva` are translated from Vasu 1909 (wisdomlib).
- **Scans**: english taken from OCR of scans (Gambhirananda, Sastri, Adidevananda, Pandurangi, Subba Rau) can still hold OCR slips.
- **Intro and colophon units** are mostly Sanskrit only.

## Two-pass approach

1. **Pass 1, clean sources.** Advaita Sharada (Sringeri, Vani Vilas edition) for every Śaṃkara Sanskrit text (Gita, Brahmasutra, all Upanishads), Setutila JSON (CC0) for Madhva Sanskrit, wisdomlib for English of the Upanishads, Mitrasamgraha TSVs, GRETIL plaintext. No OCR. Where the paired side is a scan, that side is `null` until pass 2.
2. **Pass 2, OCR backfill.** The archive.org scans marked `needs_ocr` in the corpus doc. `_djvu.txt` as a stopgap, Sarvam Vision or Tesseract where quality is too poor. Each refined file records the OCR method in `notes`.

## Tools added late

- `tools/shivaji_to_unicode.py`: decodes text typed in the legacy Shivaji01 Devanagari font (Sonde's PDFs) to Unicode, about 93-95% character agreement against our Sanskrit.
- `tools/gita_madhva_sanskrit.py`, `tools/aitareya_madhva_pandurangi.py`: fill commentary Sanskrit decoded from Sonde's Gita PDF; rebuild `aitareya_madhva` from Pandurangi's scan, OCR'd with Bodhan's IndicOCR (needs `rapidfuzz`).
- `tools/*_english.py`, `*_fill.py`, `*_sonde.py`: per-work joins of English onto the units (by verse number, by Devanagari similarity, or by content). Each reads its source from `GRANTHA_RAW`, so none can be re-run without that cache.
- Files that took English from two sources say so in `notes`; a unit never mixes sources.

## Rebuilding

`tools/` expects a cache of the raw sources in the directory named by `GRANTHA_RAW` (GRETIL txt, Mitrasamgraha TSV, Setutila `set_*.json`, `wl_cache/` of wisdomlib page text, `sribhashya_bodhan/` Bodhan OCR text of the Sri Bhashya scan, `mbtn_hariprasad/` text layer of the Nellitheertha MBTN PDF, chapter 16 PDF and `verse_en.json`, Bodhan machine translations of the Sanskrit verses used only to align). The cache is not committed.
